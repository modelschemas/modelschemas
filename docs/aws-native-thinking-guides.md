# AWS hosted thinking controls

Production parses AWS's own supported-model tables and normative parameter declarations at sync time:

- https://docs.aws.amazon.com/bedrock/latest/userguide/claude-messages-extended-thinking.md
- https://docs.aws.amazon.com/bedrock/latest/userguide/claude-messages-adaptive-thinking.md
- https://docs.aws.amazon.com/nova/latest/nova2-userguide/using-converse-api.md

The extended guide declares eight exact foundation IDs and a thinking-token budget. The adaptive guide declares twelve exact foundation IDs, a published effort table, and exact model-name restrictions on max and xhigh. A default or an effort description that says the model always thinks does not prove reasoning cannot be disabled. Mandatory values come only from explicit operational disabling statements. Adaptive is the recommended control on IDs that overlap the extended table; existing populated card controls and enum values are preserved.

Nova's hosted Converse guide names Nova 2 Lite explicitly, declares enabled and disabled types, and publishes low/medium/high maxReasoningEffort values. It produces effort mode with mandatory false. The exact native guide name joins to the model card's own title; it never expands to Nova 2 Sonic or a whole family. The wire-map thinking body remains null. Top-level reasoning_effort is not a Converse field.

Profiles receive guide facts only through the exact base/profile IDs declared on the same current AWS card. Production never strips us/eu/global prefixes to guess identity, derives aliases from examples, or creates catalog rows from guide tables. Where a guide table names a foundation ID that the current card cannot bind directly, its exact unique native model title can bind only IDs explicitly owned by the card’s bedrock-runtime access row. Haiku 4.5 consequently receives budget controls on six declared runtime profiles. Its mantle-only undated base ID stays unknown because the published runtime guide does not describe that protocol; the six runtime bindings are resolved separately. The production code never invents an alias between that base and the guide’s dated foundation ID.

Complete reasoning objects cite the guide URL and content hash only when that guide also independently supports every retained card value. Otherwise the card remains unchanged. Existing populated capability flags and sources are preserved; explicit negative capability or mandatory contradictions are visible docs errors. Strict parse/fetch failures are reported through docsFailures, and missing controls potentially supplied by a failed guide are unavailable, never source-silent. The catalog's card-owned binding cache uses a separate shape key, with actual native URLs retained in public fact provenance.

Fixtures contain complete AWS-published Markdown. Focused tests cover exact scopes, profile joins, parsed enum restrictions, positive/negative/fenced operational prose, source provenance, preserved card facts, and visible errors. A read-only live adapter audit on 2026-10-09 listed 289 current card/profile rows with zero docs failures; 59 rows cited these guides. Sixteen reasoning chat rows still lacked a mode, and three source-owned effort-mode rows still lacked a published enum; no silence exemptions are introduced here.

Converse route ownership requires both the card’s native Converse support and the exact row ID in its runtime access table. A mantle-only base cannot borrow that route or its request map from runtime profiles; those profiles keep their independently verified native binding. A native effort enum containing none does not establish disabling semantics: mandatory remains null unless the card explicitly states disabling behavior.

Converse wire maps are fetched and cached from the current first-party SDK service model (https://raw.githubusercontent.com/boto/botocore/develop/botocore/data/bedrock-runtime/2023-09-30/service-2.json). The native closed Smithy input structure establishes whether the top-level reasoning_effort field is accepted; the referenced Message role enum establishes developer-role acceptance. These two flags are parsed from current native data, rather than stored as constants. Thinking bodies, maxTokensField and unverified flags stay null. Verified endpoint provenance cites the own card and its hash; map provenance cites the actual SDK URL and fetched body hash. Failed SDK loads/parses report docsFailures and mark the map unavailable without a static substitute. Existing independently sourced replay leaves keep their own field provenance. The card-owned catalog cache shape is v2 to discard prior cached static maps.
